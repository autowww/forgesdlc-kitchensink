## Purpose

Forge **studio and app workspaces** mount governed **React primitives** (`ForgeStatusBanner`, `ForgeWorkflowStageBar`, `ForgeRunHeader`, and siblings in `react/*.tsx`) with `ks-fe-*` tokens from `css/forge-react-primitives.css`. Ad-hoc Bootstrap **`alert`** / **`badge`** markup beside those roots creates a mixed metaphor: operators see generic Bootstrap severity chrome next to catalog-governed primitives, which breaks shell integration and undermines trust in state semantics.

`collectAppShellIntegrationReport` in `design-rules/deterministic/generated/det-app-shell-integration.check.js` scans workspace scopes (`[data-studio-workspace]`, `[data-ks-app-shell]`, `.studio-page`, or `main[role="main"]`) for `.alert` / `[class*=" alert-"]` and `.badge` / `[class*=" badge bg-"]` elements that are **near** a react-primitive root (`[data-ks-react-root="true"]`, `[data-ks-type="react-primitive"]`, `.ks-fe-status-banner`, `.ks-fe-stagebar`) — within four ancestor levels or as an adjacent sibling. Findings are **minor** information-architecture defects.

**Plan:** Identify operator surfaces that mount KS primitives inside an app shell. **Do:** Route severity and status through `ForgeStatusBanner` (hash **Fsb**) or other `ks-fe-*` primitives per [FAM-react-primitives.md](../../catalog/primitives/FAM-react-primitives.md). **Check:** `appShellIntegrationReport` has no violations on crawl. **Adjust:** Remove duplicate Bootstrap banners before tuning primitive markers (**`DET.APP.PRIMITIVE_MARKERS`**) or stylesheet linkage (**`DET.APP.PRIMITIVE_STYLES`**).

## Passing signals

- Workspace scope is explicit (`data-studio-workspace`, `data-ks-app-shell`, `.studio-page`, or `main[role="main"]`) and contains only governed primitives for run status, stage, and severity — no sibling `.alert` / `.badge` beside those roots.
- Failed or warning run state uses **`ForgeStatusBanner`** with `ks-fe-banner`, variant modifiers such as `ks-fe-banner--failed`, and internal `ks-fe-banner__*` structure (see `react/ForgeStatusBanner.tsx`).
- Stage or pipeline context uses **`ForgeWorkflowStageBar`** (`ks-fe-stagebar`, `ks-fe-stagebar__node--*`) instead of Bootstrap badges on tabs or steps.
- Severity chips inside a primitive panel use `ks-fe-*` tokens or primitive props — not freestanding `badge bg-danger` adjacent to `[data-ks-react-root="true"]`.
- Bootstrap alerts/badges may still appear in **docs-only** regions outside app workspace selectors when they are not adjacent to react-primitive roots.

## Failing signals

- **`bootstrap-alert-near-primitive`:** A Bootstrap `alert` / `alert-*` sits in the same shallow subtree as a react-primitive root (for example `alert alert-danger` above `ForgeStatusBanner`).
- **`bootstrap-badge-near-primitive`:** A Bootstrap `badge` / `badge bg-*` sits beside a primitive root (for example `badge bg-warning` next to `ks-fe-stagebar`).
- Duplicate status channels: one Bootstrap alert for “Failed step” and a separate `ks-fe-banner` for the same run moment.
- Mixing Bootstrap severity colors with `ks-fe-banner--*` variants on sibling nodes — readers cannot tell which surface is authoritative.
- Hand-rolled `[data-ks-react-root="true"]` mounts with Bootstrap chrome wrapped around them instead of expanding the primitive’s `title` / `description` props.

## Evidence and remediation

1. **Crawl evidence:** `metrics.appShellIntegrationReport.violations[]` with `kind` of `bootstrap-alert-near-primitive` or `bootstrap-badge-near-primitive`, plus `tag` and truncated `className` in the finding evidence string.
2. **Replace alerts:** Remove `.alert` siblings; mount `ForgeStatusBanner` with the correct `variant` (`failed`, `warning`, `awaiting_approval`, etc.) and fold duplicate copy into `title` / `description`.
3. **Replace badges:** Use `ks-fe-stagebar__node--*` status classes or primitive props instead of `badge bg-*` beside `ks-fe-stagebar` / `ks-fe-banner` roots.
4. **Source alignment:** Ensure primitives spread `ksReactPrimitiveAttrs()` in `react/*.tsx` (**`DET.APP.PRIMITIVE_SOURCE`**) so DOM roots stay selectable and catalog-aligned.
5. **Stylesheet:** Link `forge-react-primitives.css` on pages that mount primitives (**`DET.APP.PRIMITIVE_STYLES`**).
6. **Harness:** Regenerate defect fixtures with `python3 generator/build_rule_defect_fixtures.py`, then run `tools/website-ux-auditor/auditor-tests/invoke-det-ruleset-harness.sh --only-rule DET.APP.SHELL_INTEGRATION`.
