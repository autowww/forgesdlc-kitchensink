## Required checklist axes (score each 0–100)

1. **page_identity** — H1 present; matches active nav/rail label (`DET.STUDIO.H1`, `DET.STUDIO.TITLE_NAV_MATCH`)
2. **job_budget** — one primary job in the first viewport; secondary jobs behind tabs (`DET.STUDIO.JOB_BUDGET`, `DET.APP.TAB_PANEL`)
3. **control_density** — ≤3 visible horizontal actions per group; ≤1 primary CTA (`DET.BUTTON.GROUP.MAX`, `DET.APP.PRIMARY_CTA`)
4. **human_outcome** — outcome-led lead copy (`DET.STUDIO.MECHANISM_LEAD`), clear next step
5. **wiki_functionality** — dual-wiki affordances only when the page is wiki/graph; otherwise score N/A as 100

**overall** = weighted mean of the five axes (equal weights). On non-wiki pages, wiki_functionality weight is effectively “pass” (100) so density/IA dominate.

## Calibration (avoid false positives)

- **Workflow continuity**: If row checkboxes exist, credit a contextual **Sab** (sticky action bar) that appears after selection with count + a verified next step. Do not flag `AI.APP.WORKFLOW_CONTINUITY` as major when that Sab is present and labels state scope boundaries (e.g. “Compare only”). Flag only when selection affordances exist with **no** visible outcome path in either resting or selected state.
- **Density / stacked chrome**: Mode tabs (Svc) plus one in-panel scope control (Ftb or secondary Svc) are **progressive disclosure**, not competing jobs, when **only one data table/section** is visible at a time. Penalize `AI.APP.DENSITY_BALANCE` only when two or more peer jobs (tables, builders, wikis) are simultaneously expanded.
- **Primary CTA**: `.fc-btn--ghost`, disclosure toggles (“Show details”), and “Select all” utilities are **not** primary CTAs. Count only filled/emphasized primary buttons. Do not treat two ghost utilities as violating `DET.APP.PRIMARY_CTA`.
- **Rail descriptor vs H1**: When H1 matches the active rail label, treat rail subtitle/description mismatches as **minor** `page_identity` at most — not major.
- **Pass threshold**: If `page_identity`, `job_budget`, and `control_density` are all ≥ 85 and no critical/blocker findings, prefer **warn/minor** follow-ups over major rewrites.
- **Evidence**: Cite above-fold vs below-fold. Reference `data-testid` hooks when visible in the DOM description.

## Prioritized suggestions (implementation batch)

Ranking rules (highest uplift first):

2. **Major** `job_budget` and `control_density` (competing jobs, action overload)
3. **Major** `human_outcome` (mechanism-first copy, unclear next step)

Each `prioritized_suggestions[]` entry is **one scoped remount** (not a laundry list). Do not split the same IA change across multiple ranks. Each `do[]` array must have **1–4** concrete implementation bullets for **this suggestion only**.
