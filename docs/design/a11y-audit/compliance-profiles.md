# Accessibility compliance profiles

Named **compliance profiles** bundle:

1. **axe-core** `runOnly` tags (primary WCAG automation),
2. **DET.A11Y.\*** rules whose `standards[]` metadata overlaps the profile,
3. Report/showcase metadata for procurement-oriented campaigns.

**This is not legal conformance, ADA certification, VPAT completion, or WCAG sign-off.** Pair automated runs with manual testing and, when needed, **forge-accessibility** Studio evidence.

## Layer counts (current registry)

| Layer | Count | Role |
|-------|------:|------|
| axe | ~80–100+ per run | Deque rules tagged for WCAG 2.x / Section 508 |
| DET.A11Y.\* | 68 | Forge/heuristic supplements |
| AI.A11Y.\* | 21 | Judgment overlays (`--enable-ai` + `run-website-a11y-ai-audit.mjs`) |

Profiles change **which axe tags run** and **which DET rules are in scope** — they do not multiply DET rules to match every WCAG success criterion.

## Runtime lanes vs pack tooling

| Layer | What splits DET / AI / axe | What runs at crawl time |
|-------|---------------------------|-------------------------|
| **Standards pack** (`*.pack.json`) | Each success criterion lists `rules.axe`, `rules.det`, `rules.ai` and `tooling[]` | Design-time coverage only |
| **RTM** ([`standards-traceability.generated.json`](../../tools/website-a11y-auditor/design-rules/standards-traceability.generated.json)) | Forge rules tagged `lane: deterministic` or `lane: ai` | Generated by `npm run blend-rules`; handbook: [standards-traceability-matrix.md](standards-traceability-matrix.md) |
| **analyze** (`analyze-website-a11y.mjs`) | Report groups findings by lane; `lanesExecuted` metadata | **axe + det only** in `lib/a11y-crawl.js` |
| **AI audit** (`run-website-a11y-ai-audit.mjs`) | Separate CLI + agent | Not part of default crawl |
| **Compliance score** (`score-compliance-a11y.mjs`) | `criteriaResults[].failingByLane` when site findings exist | Default crawl: **axe,det**; use `--audit-data` to score merged AI findings |

`--enable-ai` on analyze adds `ai` to the reported `lanes` set and lists **eligible** `AI.A11Y.*` rule IDs — it does **not** execute LLM prompts. After `run-website-a11y-ai-audit.mjs`, merge findings (`npm run merge-ai-audit`) then `score-compliance-a11y.mjs --audit-data …` for a combined rollup.

## Profile IDs

### WCAG 2.x

| Profile | Use when |
|---------|----------|
| `wcag22aa` | Forge default ([WCAG 2.2](https://www.w3.org/TR/WCAG22/) AA) |
| `wcag22a` | WCAG 2.2 Level A only |
| `wcag22aaa` | WCAG 2.2 AAA |
| `wcag21aa` | Procurement baseline; WCAG 2.1 AA |
| `wcag21a` | WCAG 2.1 Level A only |
| `wcag21aaa` | WCAG 2.1 AAA |
| `wcag20aa` | Legacy WCAG 2.0 A+AA |
| `wcag20a` | WCAG 2.0 Level A only |
| `wcag20aaa` | WCAG 2.0 AAA |

### WCAG 3.0 (draft)

| Profile | Use when |
|---------|----------|
| `wcag30bronze` | Draft Bronze tier — see [wcag-3.0-profiles.md](wcag-3.0-profiles.md) |
| `wcag30silver` | Draft Silver tier |
| `wcag30gold` | Draft Gold tier |

Do **not** use `wcag30a` / `wcag30aa` / `wcag30aaa` — they are rejected (not equivalent to A/AA/AAA).

### Other mappings

| Profile | Use when |
|---------|----------|
| `ada-title-ii-wcag21aa` | US state/local gov web (WCAG 2.1 AA mapping) |
| `ada-title-iii-wcag21aa` | US public accommodations web (WCAG 2.1 AA mapping) |
| `section508` | US federal ICT |
| `en301549` | EU ICT procurement baseline |
| `best-practice` | Deque extras beyond WCAG |

## CLI

```bash
node tools/website-a11y-auditor/analyze-website-a11y.mjs \
  --repo . \
  --site http://127.0.0.1:8080 \
  --compliance-profile wcag22aa
```

`--standard` is an alias for `--compliance-profile`.

## Standards traceability matrix (RTM)

`npm run blend-rules` emits packs for all RTM profiles (2.0–2.2 + WCAG 3 draft). See [standards-packs.md](standards-packs.md) and [standards-traceability.md](standards-traceability.md).
